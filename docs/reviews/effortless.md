## What it does

effortless picks the reasoning effort of each prompt, counts down the prompt cache, and offers handoffs and compactions from a band above the prompt. With its defaults:

1. Effort. Haiku 5.5 reads each prompt the person types, with the last user message and the end of the last reply, and answers a model and an effort as JSON. A slash command of the app's, a short follow-up such as "ok" and a prompt that names its level ("max effort") skip the judge. A `turn.step` hook then sends every model request of the turn at that effort, and each subagent's request at that effort or at medium, whichever is higher. It acts on Opus 5.5 and Sonnet 5.5 alone, since its author measured that an effort change rewrote the cache on Fable 5.1 and older models. A slider tips unsure calls cheaper or smarter, and a floor, a ceiling and a save mode bound the pick. With a TypeSafe key, Jev (TypeSafe's hosted judge) is asked first. Two options are off by default: an effort per subagent chosen by the judge, and routing a simple prompt to a cheaper model.
2. Cache. Each main response restarts a countdown of one hour, or of five minutes when the response's usage says its writes went to the 5-minute cache. From 400,000 tokens of context a cold cache shows an ice band with Compact, Handoff and Not now.
3. Alerts. A swamp band once the context passes 70% of the window, with Compact and Handoff. A running-hot band when the 5-hour or weekly limit passes 80%, with a save mode that caps the effort at medium until the window resets. A judge-down band when Jev fails.
4. Handoff. A bar offers Quick (a `$.model.fork` with a built-in prompt, or Haiku over the transcript when the cache is cold) or Full (the skill named in `handoffSkill`, else a turn told to check git and rewrite `HANDOFF.md` in the project root). Then Clear and carry on, Clear and wait, or Keep chat and copy. From 30% of context, Haiku is asked every second prompt whether a fresh chat would serve better, and a yes lights the Handoff button.
5. Compaction. The mod answers every compaction of the main conversation, `/compact` and the automatic one included, with a summary Haiku 5.5 writes from the transcript. If Haiku fails, the engine compacts.
6. The rest. A settings panel and a setup guide drawn in the band, an update card that installs a new version on one press, an uninstall button, an agent panel (`/effortless agents`) with a map of the files the chat touched, and the `/effortless` command with its test and debug subcommands.

It draws a dashboard band above the prompt on the desktop and in the terminal, a line under each reply in the terminal, and footer buttons on the desktop when `layout` is `minimal`.

### What could move into `session-kit`

Each is a few lines in the kit's context module, one concern per module as `A20` (one plugin, one hooks module per concern) has it, and none needs effortless installed.

1. The cache's lifetime from the response. A response's `usage.cache_creation` splits its writes into `ephemeral_1h_input_tokens` and `ephemeral_5m_input_tokens` (1195-1201), a shape the 2.1.308 types declare (`claude-code.d.ts:17818`). That fixes the fixed one-hour clock of `cache-tax`, and it is the base for the cold-send guard in `PLAN.md`. Cost: one read of the usage per response, at `turn.step` or `turn.complete`.
2. The cache on resume. On a resume or a fork, `classic.SessionStart` carries `seconds_since_last_response`, `prompt_cache_likely_expired` and `estimated_cache_write_usd` (`claude-code.d.ts:12255-12273`). effortless reads the first two (3853-3871). A resumed chat whose cache lapsed is the cheapest moment to hand off and clear, and the engine prices the other choice. Cost: one hook per session start.
3. The usage-limit line. `rateLimits`, with `five_hour` and `seven_day`, come with `session.measure` (`claude-code.d.ts:4551`), which the kit already hooks (`context.tsx:420-427`), so a line at 80% costs no new event. effortless keeps a closed band closed for its window and lets it back once at 95% (1307-1332), which fits `A43` (the bands are dismissable).
4. The fork as a cheap handoff. `$.model.fork` over the cached prefix writes a handoff in seconds with no tools (1711), and with a cold cache Haiku writes it from the transcript instead (1696-1707). That is the "one model call instead of two" that `A17` (the model signals a clear point, the mod runs the chain) leaves to try, with the same limit: neither can check git or the last test run. Cost: the kit writes `CLAUDE.local.md` from the text itself, and the two handoffs need comparing through `A22` (tooling over the sessions' transcripts and the hooks' effect) before either replaces the skill.
5. `/compact` through `$.command.run`, which waits for the session to be idle (1515-1518), in place of the chain's 20 retries of `$.session.compact` (`context.tsx:240-261`). Worth one test, since `$.session.compact` also answers a skip and `/compact` does not.

Kept out of `session-kit`: the per-prompt judge. A model call per prompt is the cost `A19` (one task per context) rejected as its option 3. It holds every prompt, against `O13` (one-off tasks are not slowed), and its saving rests on the author's four tasks, run three times each in fresh chats (README, "What it saves, measured"). `O15` (routine work takes the cheaper path) covers the model's choice of tools and gives it no ground. If the owner wants it, it belongs in a plugin of its own. The Haiku compaction waits on a measurement of its summaries against the engine's.

### What could go upstream

- Declare `updateCheck` in `types/index.d.ts`.
- The handoff race: take the handoff's text only from the handoff's own turn, by a turn id kept at `startHandoff`, and keep Go disabled while a turn runs.

- A narrower install: a `git-subdir` entry for effortless, as `textless` already has, so `docs/`, `site/` and `textless/` stay out of the plugin cache.

## Verdict: reject

Neither an install nor a fork.

- Installed as is, it breaks `session-kit` where the kit's work happens. Depending on the engine's mod order, its band hides the kit's chain and `new_task` bands and its compaction drops the backstop of `A18` (a backstop for the engine's own compaction). In any order Haiku writes the summary the chain of `A17` (the model signals a clear point, the mod runs the chain) compacts to, and the effort rewrite reaches the kit's own turns. Each can be configured away (`layout: minimal`, `compactWith: session`, Auto off), which leaves little of the mod running.
- It changes what runs on one press with no review, and it reaches GitHub at every load, against `O1` (only read code runs) and `O2` (what runs changes when I choose). The data side is clean on this machine: no TypeSafe key is set, so prompts go only to Haiku on the owner's own login.
- A fork means owning a 5,403-line module that moved through 727 commits in 17 days, for a feature whose saving is measured on four tasks and whose cost is a wait on every prompt.
- What is worth having is small and fits the kit's context module: the cache lifetime and the resume signal, the usage-limit line, and the fork handoff to measure. "What could move into `session-kit`" lists each with its cost.

If the owner wants the per-prompt effort all the same, a fork under `A2` (a fork is pinned in galileo-kit) needs these changes for its first release, each for the owner to confirm:

1. The update path removed: `latestFromGit`, `latestAvailable`, `runUpdate`, `syncRunningCopy`, the update card and Check for updates, and the uninstall button with them.
2. Jev removed, or reachable only with `judge: jev` and a key from the secret store, with `JEV_URL` ignored.
3. `compactWith` defaulting to `session`, or the Haiku compaction removed until it is measured.
4. `AbovePrompt` calling `next(e)` whenever no band of its own is needed, and the dashboard off by default.
5. The render log removed, `updateCheck` declared, the handoff race fixed, `WEIGHT.write` corrected, and the copy fallback kept off the draft.
6. The plugin trimmed to `hooks/`, `types/`, `commands/`, `.claude-plugin/` and `bench/judge-cases.json`, with `"version": "1.72.0-galileo.1"`.
