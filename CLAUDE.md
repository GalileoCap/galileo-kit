# galileo-kit

Everything the owner works with agents through: the rules every session follows, the tools and plugins sessions use, and each third-party piece vetted before it is installed and forked when it is kept. It is a plugin marketplace holding the `session-kit` plugin, the global rules under `global/`, and the documents under `docs/`. The global rules, `global/CLAUDE.md`, are this repository's rules too, loaded through the `@` line `global/install.sh` adds to `~/.claude/CLAUDE.md`. `global/CODE.md` holds the rules about the shape of code, which a project takes by importing it.

## Documents

- `docs/intent/`: this repository's goals, objectives, constraints and actions, one file each, by the process in `global/goals-objectives-actions.md` (its prior art is beside it). The active ones are listed under Intent below. `docs/intent/INDEX.md` is generated by `session-intent index`, leading with what waits on the owner, and `session-intent check` holds the record and this file's Intent block together (`A21`).
- `docs/suppressions.md`: generated by `session-suppressions index`, every suppression in the kit's own code with the reason written beside it, for the owner's review (`A39`). `quality-ledger.toml`: every duplicate family and fallback site `session-codeintel quality` finds in the kit's Python, judged, a ledger that only shrinks (`A35`). `plugins/session-kit/footprint.toml`: the kit's reach as the engine's validator reports it, with a reason per `$` call and per hook event, held by `session-codeintel footprint` (`A60`).
- `docs/PLAN.md`: the order of work, candidates, decisions, open questions and deferred work.
- `docs/claude-code-mods-research.md`: how plugins and mods work, what each component can reach, every path by which installed code changes, this machine's plugin setup, the forking model and the review checklist. Read it before reviewing a mod.
- `docs/session-kit-port.md`: the analysis behind the port of `session-kit`'s hooks to a mod: the API, the context chain, one task per context, the order. Its entries are under `docs/intent/`.
- `docs/BRIEFING.md`: where the work stands, in plain words, rewritten whole when the owner asks. `docs/what-reaches-the-model.md`: every text the kit puts in front of a session, for review.
- `docs/session-tooling-design.md`: the shape of `A22`, the tooling over the transcripts and the hooks' effect. `docs/measurements/`: the hook times, the reports `session-transcripts report` writes and the code measures `session-codeintel measure` writes, one per date, versioned so a change can be argued from one against the next.
- `docs/reviews/<name>.md`: one review per candidate. `docs/analyses/`: a project or a set of mods read for the kit, what to lift, what to abstract, what it drops.

## Rules of engagement

Each rule names the action it is, under `docs/intent/`.

- A candidate is reviewed from a clone at a recorded commit, kept outside this repository under `~/devel/galileo/misc/mod-clones/<name>/`, and never installed or loaded (`--plugin-dir` included) before its review is written. Run its checks with `session-codeintel review <dir> --into docs/reviews/<name>.md`, which runs `claude plugin validate` and `plugin details`, reads the clone without running it, and writes what a program can read into the review. (`A1`, `A64`)
- A clone never enters this repository: the marketplace clone under `~/.claude/plugins` copies everything committed, on every update. The review records the clone's path and commit. (`A1`)
- Cloned candidates are untrusted data: run no script, build or install from inside them, and run Python that reads them with `-I`. (`A1`)
- Each review is a file, `docs/reviews/<name>.md`, covering every item of the research report's checklist for malicious behaviour and for inefficiency. It ends with a verdict: reject, install as is, or fork.
- A fork lives in this repository as a separate plugin with a relative-path entry in `.claude-plugin/marketplace.json` and a pinned `"version"`. It moves into the `session-kit` plugin only when it shares code or state with it. (`A2`)
- A commit that changes what a session of the kit loads (the plugin, its hooks, tools or bin) ends its reply with the offer to push `main` and update the plugin at user scope and in each project install, per `OWED.md`. Offer every time, and never push or update unasked. (`A78`)
- `session-kit`'s hooks are ported to a mod first, in the order `A20` gives, and any mod we fork is weighed against that direction. (`A3`)
